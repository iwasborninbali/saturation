# Скрипты, на которые ссылаются ЖИВЫЕ прогоны, носят суффикс стороны

Правило предложено первым решателем 2026-08-21 после случая, которого у нас ещё не было.

Мы оба независимо написали `work_unit.sh`, делающие похожее. При слиянии они столкнулись;
разрешили сохранением обеих версий. Дальше произошло вот что: **идущий прогон первого
решателя вызывал `work_unit.sh` по имени и после слияния начал вызывать версию второго.**
Ошибок не случилось, прогон перенаправили за минуту.

Весь этот день мы ловили подмену ДАННЫХ — временный файл, чьё имя не несло базу, писал
UNSAT чужой формулы под именем своей (280 отозванных фактов). Это подмена КОДА: имя файла
не несло стороны, и слияние сменило исполняемый файл под руками работающего процесса.
Класс тот же — имя не различало то, что обязано было различать.

Правило:
  * скрипт, который может быть вызван живым прогоном, называется с суффиксом стороны
    (`_second`, `_first_solver`);
  * общее имя остаётся свободным — за него никто не борется;
  * машины держат СВОИ копии, доставленные scp, а не читают из рабочего дерева репозитория:
    тогда `git pull` физически не может подменить исполняемый файл идущему прогону.
