# Указатель журналов и сертификатов

**Правило (принято обоими солверами):** любое число в тексте несёт ссылку на файл и строку журнала,
которые его дали. Число без ссылки считается НЕПРОВЕРЕННЫМ независимо от того, кто его написал.

Синхронизация с вычислительных машин: `slack/targets/sync_journals.sh`. Запускать перед каждым
коммитом, где появляются новые числа. Существует потому, что незалитый журнал мы уже теряли.

## Что где лежит

| каталог | содержимое |
|---|---|
| `logs/sweeps/` | прогоны по гиперболам (k = ±1, пары, четвёрки) — закрытое направление |
| `logs/no3_3d/` | no-three-in-line в кубе: доказательство n = 5, нижние границы n = 6…10 |
| `logs/a280537/` | без четырёх компланарных: калибровка n = 2…5, оценки стоимости n = 5…7 |
| `certs/a280537/` | свидетели-конфигурации и **независимый** проверяльщик `verify_witness.py` |
| `certs/no3_3d/` | свидетели для трёхмерного no-three-in-line |

## Отрицательные результаты — хранятся наравне с положительными

- `logs/no3_3d/vm2_n5_results_VOID_killed.txt` — 150 строк, ПРИЗНАНЫ НЕДЕЙСТВИТЕЛЬНЫМИ: процессы были
  убиты `pkill`, обёртка засчитала пустой вывод как успех. Ловушка «killed ≠ finished», из-за неё
  переписана обёртка (`run_prefix.sh` печатает OK/FAIL) и проверялка покрытия.
- Направление «константа для пары гипербол» закрыто как исчерпанное на 3.44817(p−1); все локальные
  маршруты сертификата измерены и упёрлись в потолок. См. `docs/ROADMAP_hyperbola_archive.md`.
- Полная перепись rot2 при n = 32 признана невозможной: ≈5.7·10¹⁸ узлов, разрыв ~2·10⁵ раз не
  закрывается ни числом машин, ни оптимизацией. См. дополнение к брифу 9.
- Первая версия `plane4.c` (перечисление плоскостей по коэффициентам) давала n = 4 → 11 вместо 10;
  ошибка и её причина описаны в `docs/research/targets/audit_A280537.md`.
- Ресёрчи 10 и 11: все 25 рассмотренных кандидатов отвергнуты. Это результат, а не провал —
  см. `docs/research/deep_research_11_answer.md`.
