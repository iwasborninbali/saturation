Калибровка счёта по классу rot2 против таблицы Фламменкампа
===========================================================
Таблица: https://wwwhomes.uni-bielefeld.de/achim/no3in/table.txt (last update 31.01.1997)
Столбец `all` совпадает с A000755 — то есть таблица и последовательность согласованы.

ЛОВУШКА, В КОТОРУЮ МЫ УЖЕ ПОПАДАЛИ И ЧУТЬ НЕ ПОПАЛИ СНОВА

Наши числа для sym=1 (67, 144, 276, 784) НЕ совпадают с его столбцом `:` (13, 33, 61, 189).
Ошибки нет — это РАЗНЫЕ ВОПРОСЫ, и их два сразу:
  1. у него стабилизатор РАВЕН полуобороту, у нас — СОДЕРЖИТ его;
  2. у него КЛАССЫ ЭКВИВАЛЕНТНОСТИ, у нас ПОМЕЧЕННЫЕ конфигурации.

Связь: помеченных = сумма по классам, содержащим rot2, с весом «размер орбиты = 8/|стабилизатор|».
Классы, содержащие полуоборот: `:` (порядок 2), `x`, `o`, `+` (порядок 4), `*` (порядок 8).

  n=10:  13*4 + 1*2 + 6*2 + 0*2 + 1*1 =  67   наш счёт  67   СОВПАЛО
  n=12:  33*4 + 2*2 + 4*2 + 0*2 + 0*1 = 144   наш счёт 144   СОВПАЛО
  n=14:  61*4 + 3*2 + 13*2 + 0*2 + 0*1 = 276  наш счёт 276   СОВПАЛО
  n=16: 189*4 + 1*2 + 13*2 + 0*2 + 0*1 = 784  наш счёт 784   СОВПАЛО

Четыре точки, связь нетривиальная. Счётчик верен.

Это ТРЕТИЙ раз, когда одно имя `rot2` даёт разные числа, и в нашем регламенте это записано
дословно: «под словом rot2 пряталось ЧЕТЫРЕ разных числа, и наши 36 и 67 были верны, но
отвечали не на тот вопрос». То же самое 67, тот же n=10. Правило было записано — и всё равно
понадобилось вывести связь заново, чтобы не объявить ошибкой то, что ошибкой не является.
Вывод: правило о разных счётчиках одного объекта НЕ спасает само по себе; спасает только
явное построение перехода между ними.

СТОИМОСТЬ (одно ядро): n=10 0.01 с, n=12 0.09 с, n=14 2.23 с, n=16 17.59 с — около 2.8x на шаг.
Это НЕСРАВНИМО дешевле класса без симметрии (там n=16 стоил бы 29 суток).

НЕЧЁТНЫЕ n: отдельная ветка кода, отдельная сверка, и разрешённое расхождение
==============================================================================
В there.c для нечётных n своя ветка. Свойство, проверенное на чётных, на нечётные не
переносится само — проверено отдельно.

Сперва вышло расхождение: n=17 дал 1128 против предсказанных 1130. Разница ровно 2.
Гипотезы были три: (а) счётчик пропускает конфигурации; (б) я неверно читаю таблицу;
(в) ошибка в таблице 1997 года.

РЕШАЮЩИЙ ОПЫТ, и он не потребовал нового счёта. Столбец `sum` у Фламменкампа —
«число решений, не эквивалентных под преобразованиями симметрии», то есть сумма классов.
Проверка его арифметики:
  n= 9: . 41 + / 3 + : 7 + x 0 = 51 = sum;  с добавлением c=1 вышло бы 52 — НЕ сходится
  n=11, 13, 15: сходится и так, потому что там c = 0
Значит столбец `c` (rct4) — НЕ ячейка разбиения, а ПОМЕТКА ВНУТРИ другого столбца.
Добавлять его в переход через орбиты нельзя.

Подтверждено и прямо: перечислив все 1128 конфигураций при n=17 (PRINTALL), нашли среди
них ту самую rct4-конфигурацию. Счётчик её НЕ пропускает — она входит в 282 класса
столбца `:`.

ФОРМУЛА для нечётных n: помеченных = `:`*4 + `x`*2 + `*`*1   (без `c`).
  n= 9:   7*4 + 0 =   28   наш счёт   28   СОВПАЛО
  n=11:  30*4 + 0 =  120   наш счёт  120   СОВПАЛО
  n=13:  82*4 + 1*2 = 330  наш счёт  330   СОВПАЛО
  n=15: 283*4 + 1*2 = 1134 наш счёт 1134   СОВПАЛО
  n=17: 282*4 + 0 = 1128   наш счёт 1128   СОВПАЛО

ИТОГО десять сверенных точек: чётные 10,12,14,16,18 и нечётные 9,11,13,15,17.

ЧТО ИЗ ЭТОГО СТОИТ ЗАПОМНИТЬ. Расхождение разрешилось НЕ новым вычислением, а внутренней
сверкой уже имевшихся данных: столбец сумм противоречил моему прочтению столбца классов.
Ответ лежал у меня на диске с самого начала — я просто не задал таблице правильный вопрос.
И вторая половина: расхождение оказалось МОЕЙ ошибкой чтения, а не ошибкой инструмента и не
ошибкой таблицы. Держать его как ОТКРЫТЫЙ ВОПРОС, а не как найденную ошибку, было верно —
объяви я «в таблице Фламменкампа ошибка», пришлось бы забирать слова обратно перед автором.
