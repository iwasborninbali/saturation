# Журнал гипотез — resolution 71 (2n = 142)

Формат: **Hk. Вопрос** → метод → исход. Всё, что называется фундаментом, прошло `the_law`;
ключи canon и списки токенов лежат в `results/`.

## Кадр
- Пространство: клетки решётки 71×71, токен t = u*71 + v. Закон: никакие три токена не коллинеарны
  (разности ранга 2). Потолок 2n = 142 (≤2 на строку). Восемь движений = группа D4 квадрата.
- Семя `seeds.quadratic_opening`: {i*71 + i² mod 71}: размер 71 (парабола над F_71 — дуга).

## H1. Коники по модулю q<71 в коробке 71: даёт ли алгебра больше 71 без поиска?
Метод: `h1_conics.py`, `h1b_hyper.py` — параболы/гиперболы/окружности/случайные коники mod q, q∈[29,97];
жадный ремонт (удалять точку с макс. числом троек), затем жадное дозаполнение.
Исход: чистые (без ремонта) законные множества до **88**: (x+18)(y+18) ≡ 35 (mod 53), все клетки коробки.
После ремонта+жадного дозаполнения — 105–110 независимо от семени (парабола y=x²+72 mod 73 → 110).
Вывод: алгебра даёт ≈1.24n «бесплатно», жадный слой сверху ≈1.5n; выше — только поиск.

## H2. Отжиг (fast/sa.c): случайные ходы (перенос/обмен/отражение орбит), штраф = число троек, ≤2 в строке/столбце.
Вопрос: как высоко растёт законная книга при n=71 за 600 с в разных классах симметрии, и каков min троек при K=142?
Исход (600 с, 1 ядро на прогон):
- рост: rot2 → **126**, diag → **126**, v2 → 120 (T=0.3 мала для орбит размера 4, акцепт≈0), id → 114 (116 от семени 110).
- K=142 (min троек): id 37 (T=0.35 const), id anneal 0.6→0.2: 46, rot2 40, v2 126 (заморожен).
Калибровка на малых n (K=2n): n=10,12,14 насыщаются за секунды; n=16..28 за 60 с не насыщаются (min троек 1..7).
Вывод: симметрия помогает росту (меньше степеней свободы), акцепт случайных ходов ~0.3% — нужен направленный выбор целей.

## H3. Min-conflict с полем пар (fast/mc.c): F[c] = число пар состояния, коллинеарных с клеткой c (обновление обходом прямых);
ход = убрать конфликтную орбиту (или две), вставить орбиту с минимальным ΣF (жадно), Метрополис при T.
Вопрос: выше ли растёт законная книга при n=71 за 600 с, чем у sa.c?
Исход: id → **131** (за ~45 с 131, далее плато K=132 с 1–2 тройками), rot2 → 130, diag → 128, v2 → 124.
K=142 (min троек): id 51, rot2 42 — хуже sa.c по этому показателю (в 20 раз меньше итераций/с).
Вывод: направленный выбор целей ускоряет рост в разы; фронт ≈130–132 за 10 минут на ядро.

## H4 (фланг). Какие подгруппы восьми движений допускают насыщение (142) при нечётном n?
Доказательство (n=2h+1, m=n−1, центр (h,h); в насыщенной книге ровно 2 токена в каждой строке и столбце):
- отражение h: (u,v)→(m−u,v). Строка h содержит ровно 2 токена (h,a),(h,b). Столбцу a нужен второй токен (u,a), u≠h,
  но тогда и (m−u,a) в книге — три токена в столбце a. Противоречие ⇒ классы {e,h}, {e,v} (симметрично), V1={e,r²,h,v}, D4 пусты.
- поворот r (порядок 4): орбиты размера 4 кроме центра ⇒ |B| ≡ 0 или 1 (mod 4), но 2n = 4h+2 ≡ 2 ⇒ C4 (и D4) пусты.
- rot2: центр невозможен (иначе |B| нечётно); остальное — 71 пара {P, r²P}. Допустим арифметически.
- diag: неподвижная диагональ содержит 0 или 2 токена; остальное — пары {P, dP}. Допустим.
- V2={e,r²,d,d'}: центр невозможен (иначе |B|=1+2(a+a')+4g нечётно); ровно одна пара размера 2 на одной из диагоналей
  (2n=2(a+a')+4g, a,a'∈{0,1} ⇒ a+a'=1) и g=h=35 орбит размера 4, ровно одна из них вида (35,v).
Проверка перебором (fast/bt.c, полное исчерпание): при n=3,5,7,9 классы h,v,c4,d4,hv дают 0 решений; по Бернсайду
из классовых счётчиков получаются 1,1,4,5,11,22,57,51,156 неэквивалентных насыщений для n=2..10 (валидация кода).
Трассы исчерпания V2 при нечётных n (order=1, узлы/решения/сек):
n=11: 868/0/0.00; 13: 3433/2/0.01; 15: 15411/2/0.10; 17: 60331/0/0.46; 19: 297462/0/1.9; 21: 1476124/0/8.7; 23: 6965455/2/46;
25: 33773630/4/257 (полно); 27: >146M узлов за 900 с (не завершено, 0 найдено); 29: >117M за 900 с (не завершено, 0).
rot2: n=11: 147314/120/0.26; 13: 2294863/330/4.7; 15: 51311689/1134/120. diag: 11: 195699/12; 13: 3655829/20; 15: 77878222/28/172 с.
Вывод: V2 — самый маленький допустимый класс, решения в нём спорадичны (n=3,13,15,23 — по одному, n=25 — два с точностью до движений);
рост дерева ×4.7–4.8 на +2 к n (7.0M→33.8M при 23→25) ⇒ при n=71 порядка 10²³ узлов: исчерпание любого допустимого класса при 71 недостижимо здесь.

## H5. Табу/крутейший спуск/температура для mc при n=71 (раунды 3–4, 300–900 с, по 12 конфигураций).
Вопрос: какие параметры и какой класс дают максимальный рост?
Исход (300 с): rot2+табу20 (T=0.4, шум 0.1) → 132, 132; id без табу → 131; id табу100 → 126; T=0.6 или шум 0.2 → 126–128 (уход в конфликты).
Исход (900 с): rot2+табу20 → **134**, 132, 132, 132; id → 132, 130, 130, 130; diag → 128, 128; v2 (T=0.8/1.0) → 128/124.
Профиль улучшений одного rot2-прогона: 130 за 1 с, 132 за 39 с, 134 за 424 с — каждые +2 ≈ ×10 времени.
Вывод: класс rot2 (67 пар {P, r²P}) — лучший носитель роста; умеренное табу (20) помогает; больше — вредит.

## H6. Точная (r,r+1)-полировка (fast/polish.c): есть ли у найденных 132/134 обмены 1→2, 2→3, 3→4?
Исход: нет — книги 132 и 134 (r,r+1)-swap-оптимальны при r≤3 (проверка < 0.2 с; на жадных множествах при n=10..20 полировщик находит обмены — инструмент исправен).
Вывод: случайный min-conflict уже неявно исчерпывает такие обмены; следующий уровень — плато большей глубины.

## H7. Продолжение без симметрии (id) из симметричных 132/134: снимает ли снятие симметрии потолок?
Исход (900 с, 8 прогонов): из 134 → 134 (K=135 с 1–2 тройками), из 132 → 132–133. Прироста нет за 15 мин.
Параллельно 4 свежих rot2 (табу20): один дошёл до 134 за ~5 мин, остальные 130–132.

## H8. LNS с точным ремонтом (fast/lns.c): разрушить компактный кластер из r орбит (r=2..16), точным DFS по допустимым
орбитам (F=0 на всех клетках) найти максимум вставляемых; больше r ⇒ рост.
Исход: из 134 (rot2): 330 тыс. итераций при r≤8 и 770 при r∈[8,16] (бюджет 50k узлов, в среднем 3.3k) — ни одного роста,
все ремонты ровно возвращают счёт; из 128 — то же (в среднем 11 допустимых орбит после разрушения 4–12).
Вывод: блокировка клетки — глобальное свойство (пара где угодно, прямая через клетку): пространственное разрушение
почти ничего не освобождает. Ходы через незаконные состояния (mc) — существенно более широкая окрестность.

## H9 (калибровка). Насколько близко mc2 (rot2, табу20, 300 с) подходит к 2n при n, где насыщение точно достижимо (перебор bt даёт решения)?
Исход: n=20: 38/40; n=30: 58/60; n=40: 76/80; n=52: 96/104; (n=71: 134/142 за ~15 мин × 12 ядер).
Вывод: разрыв метода 2n − best растёт с n (2, 2, 4, 8, 8): недостача 8 при 71 — предел метода, а не свидетельство
недостижимости 142. Локальный поиск не находит 2n даже при n=20 за 5 мин, тогда как точный перебор с симметрией — за секунды.

## H10. Продакшн (1 ч × 8 rot2 mc2) и финальный раунд (40 мин × 11 rot2 mc3 со STUCK: 6 стартов из трёх разных книг 134 + 5 свежих).
Вопрос: даёт ли больше времени/перезапусков 136?
Исход: продакшн — ещё одно 134 (за 64 с!) и семь 132; финал — все шесть стартов из 134 держат K=136 с 4–6 тройками
40 минут, ни одного законного 136; свежие: одно 134, четыре 132. Итого пять различных книг 134 (разные canon-ключи), 136 — нет.
Вывод: 134 → 136 стоит существенно больше ~10 ядро-часов при текущем ходе (+2 токена одной rot2-орбитой ⇒ сразу 4–6 троек).

## H11. Прямая атака на 142 (K=2n, обмены столбцов между орбитами, min троек):
