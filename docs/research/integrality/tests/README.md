# tests/ — тесты на НЕПОЛНОТУ спецификации

Объект изучения — `../phenomenon.py` и `../holes.py`. **Они не правятся.** Спецификация здесь
не код, который надо чинить, а теория, которую надо атаковать; правка стирает улику.

Только stdlib (`unittest`), Python 3.14. `pytest` не установлен.

## Как запускать

```sh
cd docs/research/integrality

python3 -W ignore -m unittest discover -s tests -t tests -v    # весь набор
python3 -W ignore tests/test_principles.py                     # один файл (каждый самодостаточен)
python3 -W ignore tests/gaps_report.py                         # реестр дыр в markdown → stdout
python3 -W ignore tests/gaps_report.py --write                 # перегенерировать середину GAPS.md
```

`-t tests` обязателен: в `tests/` нет `__init__.py`, поэтому это не пакет, и при `-t .`
discover падает сразу — `ImportError: Start directory is not importable`. С `-t tests`
корнем импорта становится сам каталог, и модули зовутся `test_x`.

Отдельно от этого `gaps.py` защищён от двойной регистрации: если один и тот же файл
импортировать под двумя именами модуля, декораторы `@gap` сработают дважды и второй прогон
упадёт с `RuntimeError: duplicate gap id GAP-C-01`. Это защита, а не поломка — id обязаны
быть уникальны по всему набору.

`-W ignore` глушит `SyntaxWarning` из `phenomenon.py`: докстринг модуля не raw-строка, и
`"\ "` — недопустимая escape-последовательность (видно только при перекомпиляции, из-за
кэша `.pyc`). Предупреждение настоящее и запинено тестом; флаг лишь убирает шум из вывода.

Ожидаемый результат: `OK (expected failures=36)`. Порядок модулей не важен — проверено
прогоном в обратном порядке; два теста, трогающих общее состояние (`P.OUR_SIGNATURE`,
`P.Frame.strength`), восстанавливают его в `finally`.

## Три сорта тестов

| сорт | что утверждает | цвет, пока всё как есть |
|---|---|---|
| **обычный** | инвариант, который ДЕРЖИТСЯ: спецификация в этом месте говорит правду | зелёный |
| **запиненный дефект** | поломка, которую видно ПРЯМО СЕЙЧАС: `raise`, зависание, неверное число | зелёный (утверждается сама поломка) |
| **`@gap`** | то, чего в спецификации НЕТ, хотя по её же тексту обязано быть | зелёный через `expectedFailure` |

Граница между вторым и третьим сортом жёсткая. Если дефект можно предъявить прямо —
`verdict()` печатает «4/4», игрушка виснет, число противоречит заметкам — это ОБЫЧНЫЙ тест,
утверждающий сломанное поведение, и он пинит его навсегда. `@gap` остаётся для другого:
для утверждения, которое ДОЛЖНО было бы выполняться по докстрингам, но не выполняется,
потому что нужной сущности в спецификации нет вовсе.

Каждая дыра проверена с двух сторон: она падает на том утверждении, которое названо в её
докстринге (а не на импорте, опечатке или придирке к имени поля), и она ПРОХОДИТ против
смоделированной исправленной спецификации. Дыра, которая не может позеленеть ни при какой
починке, — не дыра, а вечный xfail; такие на ревью снимались.

## Почему «unexpected success» — это КРАСНЫЙ прогон, и так задумано

`@gap` вешает `unittest.expectedFailure`. Пока дыра открыта, тест падает — и прогон зелёный:
отсутствие зафиксировано машинно, а не в чьей-то памяти. Как только дыру закроют — допишут
в `Signature` поле для целочисленного оптимума, привяжут порог в P3, разведут H4 и цель —
тест начнёт проходить, `unittest` доложит `unexpected success`, и прогон станет КРАСНЫМ.

Это не ложная тревога. Красный здесь означает: «спецификация изменилась, реестр устарел,
снимите маркер и перепишите запись». Без этого список дыр тихо разошёлся бы с файлами,
которые он описывает, и `GAPS.md` — документ, уходящий во внешний дип-ресёрч, — начал бы
рассылать неправду о том, чего в проекте не хватает. Список `@gap` = список «чего нет»,
и устареть незаметно он не может.

## Файлы

| файл | что делает |
|---|---|
| `gaps.py` | декоратор `@gap` + `REGISTRY`; падает на повторном id |
| `test_contracts.py` | типы, поля, `Enum`, что объявлено и не используется (`GAP-C-*`) |
| `test_numbers.py` | числа модуля против данных проекта (`GAP-N-*`) |
| `test_toys.py` | три игрушки: что они на самом деле демонстрируют (`GAP-T-*`) |
| `test_principles.py` | P1–P5 и признаки: контрпримеры (`GAP-P-*`) |
| `test_holes.py` | полнота и независимость набора H1–H8 (`GAP-H-*`) |
| `test_falsifiability.py` | что вообще способно опровергнуть теорию (`GAP-F-*`) |
| `gaps_report.py` | markdown-реестр всех дыр |
| `GAPS.md` | реестр + предисловие; вход для дип-ресёрча |

Игрушки в `phenomenon.py` содержат безусловные `while`. Тесты, проверяющие зависание,
запускают их в подпроцессе с таймаутом и утверждают `subprocess.TimeoutExpired`; в самом
процессе с плохими аргументами их звать нельзя — набор обязан не виснуть никогда.

Номера `GAP-H-05` и `GAP-P-04` пропущены: обе кандидатуры отвергнуты на ревью как
педантичные, содержательный остаток переведён в обычные тесты. Номера не переиспользуются.
