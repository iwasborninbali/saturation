# Самопроверка заметки перед публикацией: каждое число против артефакта

Сделано 2026-08-20 перед передачей на независимый разбор. Метод один и тупой: выписать КАЖДОЕ число
из текста и найти файл, который его порождает. Число без файла считается непроверенным, кто бы его
ни написал.

Проверка нашла **две ошибки в тексте, который собирались публиковать**. Обе — не в вычислениях,
а в связи между текстом и вычислениями.

## Найдено и исправлено

**1. Нижние границы без свидетелей.** В тексте стояло `a(7) >= 72`, `a(8) >= 90`. Артефактов под этими
числами НЕТ; воспроизводимые журналы дают 71 и 89. Происхождение 72/90 установить не удалось —
вероятно, ранний прогон, чей вывод не сохранился. Исправлено на 71 и 89; наборы извлечены из журналов,
проверены перебором всех троек, сохранены как `certs/no3_3d/witness_n7_71.txt`, `witness_n8_89.txt`.
В тексте заметки расхождение названо прямо, а не переправлено молча.

**2. Число приписано методу, который его не порождал.** Оценка `4.6e22` узлов для n=6 подана как
результат СТРАТИФИЦИРОВАННОГО оценщика, тогда как получена обычным Кнутом — тем самым, который мы
позже сами дисквалифицировали (на родственном дереве среднее по 20000 спусков на 89 % состояло из
одного спуска). Стратифицированной версией это число не пересчитывалось. Формулировка исправлена:
сказано, каким инструментом получено, что инструмент оказался ненадёжен на деревьях этого семейства,
и что читать число следует как порядок величины.

## Проверено и подтвердилось

| число в тексте | чем подтверждено |
|---|---|
| a(1..6) = 1, 8, 16, 28, 40, 64 | `logs/no3_3d/FINAL_VERDICT.txt`: покрытие 256/256 и 484/484, все куски невыполнимы |
| свидетели 40 и 64 точек | 9880 и 41664 троек, 0 коллинеарных; при n=6 — два независимо добытых |
| a(7) >= 71, a(8) >= 89 | свидетели извлечены и проверены (см. выше) |
| a(p) >= p^2 | доказательство в тексте; проверено при p = 3, 5, 7, 11, 13 |
| семантика кодировки, n=6 | 5696 против 5696, 0 расхождений в обе стороны |
| семантика кодировки, n=7 | 16427 против 16427, 0 расхождений |
| симметрийное отсечение | два независимых способа (вызовы решателя и прямое вычисление клауз), 0 смертельных при n = 3, 5, 6, 7 |
| узлы 17 / 20068 при n = 2, 3 | пересчитано заново |
| узлы 3855 / 4.21e7 (второй перечислитель) | подтверждено при калибровке на другой машине |
| планарные максимумы 11/4, 32/5, 50/11 | пересчитано СВОИМ кодом независимо от первого солвера: 11 конфигураций в 4 классах (4x4), 32 в 5 (5x5), 50 в 11 (6x6) |
| профиль 10,6,8,6,10 невозможен при n=5 | сильная (одноосная) форма, проверено обоими солверами |
| профиль 14,12^5,14 невозможен при n=7 | сильная форма, UNSAT за 29 с |
| стратифицированный оценщик, 0.1 % при n=4 | 1 771 000 против точных 1 769 732 |
| «89 % среднего от одного спуска» | 20000 спусков, доля максимума в сумме |
| последовательности нет в OEIS | поиск `1,8,16,28,40` и `8,16,28,40,64` — пусто |

## Вывод для регламента

Обе найденные ошибки — одного класса: **текст утверждал больше, чем порождающий его файл**. Ни одна
не была ошибкой вычисления. Значит проверка вычислений, сколь угодно тщательная, их не ловит, и
сверка «текст против артефактов» обязана быть отдельной стадией перед любой публикацией.

Занесено в `docs/research/targets/SELECTION.md` как продолжение правила о провенансе.
