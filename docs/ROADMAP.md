объём точного счёта, исчерпывающий перебор, перекрёстная проверка, отрицательные результаты, вычисление того, что все предполагают и никто не считал.

## 1. АКТИВНО: no-three-in-line в [n]³ (трёхмерный аналог)
**Зачем:** жанр «никто не считал»; проверено — точных значений в литературе нет (Pór–Wood 2007 дают только асимптотику Θ(n²); в OEIS есть A157882
«число коллинеарных троек в кубе», но не максимум). Результат — запись в OEIS плюс короткая заметка.
**Целевой объём:** доказанные точные значения n = 2…5 + сертифицированные нижние границы n = 6, 7, 8.

| id | задача | исполнитель | состояние |
|---|---|---|---|
| 3D.1 | точные значения n = 2, 3, 4 | оба, независимо | ГОТОВО: 8, 16, 28 — двумя разными алгоритмами, узлы 17/3855/4.21·10⁷ (первый) против 17/20068/3.03·10⁹ (второй) |
| 3D.2 | оценка стоимости доказательства n = 5, 6 | второй | ГОТОВО: оценщик Кнута, откалиброван против истины (ошибка 3–4 %). n = 5 ≈ 2.4·10¹⁴ узлов (посильно), n = 6 ≈ 4.6·10²² (невозможно) |
| 3D.3 | ДОКАЗАТЬ n = 5 (решающая форма: рекорд 40, показать что 41 нет) | первый (52 префикса, 11 ядер) + второй (144 префикса, 42 ядра) | ИДЁТ, ожидание 12–18 ч |
| 3D.4 | нижние границы n = 6, 7, 8 | второй (стохастика) | 64 / 71 / 89, все проверены; n = 7, 8 недобраны (отношение к n² падает) — считается дольше |
| 3D.5 | независимый сертификатор свидетеля | второй | к работе после 3D.3 |
| 3D.6 | оформление записи в OEIS + заметка | оба | после 3D.3 |

**Разделение и его правило:** реализации НЕ сливаем. У первого — DFS с орбитным разбиением и отсечением по z-столбцам; у второго — include/exclude с
масками коллинеарности. Сверяем только ответы. Совпадение при 72-кратной разнице в числе узлов и есть сертификация.

## 3. ЧТО ПОСТРОЕНО И ПЕРЕИСПОЛЬЗУЕТСЯ (главный актив, важнее любой константы)
- **Оценщик размера дерева (Кнут)** — `slack/t221/cube3.c`, режим ESTIMATE. Откалиброван против истины. Даёт цену ДО начала счёта.
  Тонкость: затравку рекорда задавать известным оптимумом, иначе меряется другое дерево (промах в 13 000 раз).
- **Протокол C2** (первый солвер, в SELECTION.md): калибровка против опубликованного числа → замер отношений роста → две оси → проверка предасимптотики → вердикт одной строкой.
- **Независимые верификаторы**: `slack/t221/verify_family.{py,c}` (семейства), `census_rot2.c` (rot2-перепись), `cube3.c` (3D).
- **Дисциплина сертификации**: любое утверждение о полноте — только после сверки с независимо вычисленной истиной. Поймало два дефекта за сутки.
- **Доступ к OEIS**: стандартный инструмент получает 403; работает `curl -A "Mozilla/5.0" "https://oeis.org/search?q=...&fmt=json"`.

## 5. Замеры по 3D, добавленные 20.08 (ночь)
- Нижние границы (стохастический поиск, все проверены перебором троек): n = 5: 40, n = 6: 64, n = 7: **72**, n = 8: **90**.
  n = 7 совпал с CP-SAT первого солвера (72), то есть подтверждён двумя способами.
- Алгебраические конструкции ПРОВЕРЕНЫ И ОТВЕРГНУТЫ (`slack/t221/alg3d.py`): для простых n поверхность z ≡ x²+y² (mod n)
  даёт ровно n² точек без трёх коллинеарных (25 при n = 5, 49 при n = 7) — красиво и доказуемо, но СЛАБЕЕ поиска
  (40 и 72 соответственно). В отличие от двумерного случая, где вся сила была в алгебре, здесь она не даёт ведущей константы.
  Полезно как ДОКАЗУЕМАЯ нижняя граница n² для простых n, а не как рекорд.
